# 固定评测执行批次与结果归档（V41）

## 解决的问题

此前 RAG 评测逐题读取知识库配置，模型工厂按名称复用客户端，自动生成数据还会扫描物理分块。知识库发布或模型配置在运行中变化时，同一个任务可能混合多个版本；逐题异常被跳过后，剩余样本仍可能被标记为完整成功。重试删除旧 QA，也会丢失失败批次的原始结果。

V41 为每次可靠任务执行建立独立批次。执行期间固定已发布语料、知识库配置和模型目录的私有副本，使用批次内客户端，并保存输入、逐题结果及完成清单。一次重试产生新批次，不能覆盖旧归档。

## 执行协议

1. 以可靠 Job 的当前租约进入执行，重新检查创建人的知识库读取权限。禁止绕过可靠任务直接运行评测。
2. 复制知识库配置和模型目录，建立独立的已发布索引读视图。清单记录发布集合指纹、文档代际及源指纹、检索配置、评测模式、Top K、提示词和主要执行类的指纹。
3. 在短事务中按 Job → Task 的顺序锁定归属，登记 RUNNING 批次、清空当前展示指标及 QA。失联的上一批次记为 INTERRUPTED，历史归档保留。
4. 冻结本批实际问题集及 SHA-256；输入 JSON 最大 4 MiB。导入样本先复制，生成样本只从固定发布集合抽取，抽样种子来自发布版本。生成问题的时间戳和任务 ID 不进入问题集指纹。
5. 每题使用知识库配置副本。模型选择只查询批次目录，歧义、禁用、缺失或不支持的配置直接使批次失败，禁止静默更换供应商或模型。客户端实例不受全局缓存清理及目录后续修改影响。
6. 每题结果与当前 QA 在同一事务提交，同时核验 Job 租约和当前批次指针。结果归档保存回答、指标和检索上下文摘要；完整检索上下文仍在当前 QA 中，归档不复制其正文。
7. 必须完成全部输入样本才能提交 COMPLETED；最终清单包含实际模型绑定、输入指纹、逐题结果指纹和结果数。批次完成与任务指标在同一事务提交。

模型或检索异常即使被普通服务的降级逻辑捕获，也会使评测作用域失效。空向量、未完整评审、失败后跳题都不能产生完整成功。普通在线请求保留现有降级行为。

若完成事务已提交、Job 尚未来得及确认便中断，重新接管时识别已完成批次，避免再次调用模型。若执行被取消或重试耗尽，恢复扫描器处理遗留 RUNNING 批次；它不会伪造缺失结果。扫描默认每 30 秒运行，每批最多处理 100 个候选任务。

## 配置与保密边界

模型目录私有副本中的密钥只在内存中使用，不写入批次清单。实际模型描述记录配置 ID、供应商、模型 ID、配置更新时间、端点摘要、已配置参数、工厂/客户端类及指纹；密钥和原始端点不进入此归档。模型目录摘要也排除密钥。

这里固定的是应用侧配置和客户端，不承诺冻结供应商侧权重、随机输出、服务端默认行为或外部业务状态。部分参数仍使用 SDK 默认值，清单明确标记 `sdkDefaults`；类指纹也不等于完整构建或依赖锁文件。旧代际缺少源指纹时会原样记录缺失，不补造证据。

读者租约最长一小时；超时后拒绝结果，不能继续把晚到响应记为有效成功。批次完成后释放租约，历史归档不会永久保留 ES 向量。它支持结果审计，不代表已实现历史语料任意重放。

## 基线可比性

基线必须是同一创建人、知识库、评测模式和 Top K 的已完成批次，并与当前批次具有相同的实际输入及发布集合指纹。没有可比指标、历史任务缺少批次、语料或问题集变化时，显示 `INCOMPARABLE`（不可比）。不能把“不可比”当成回归通过。

模型或检索配置可以不同，这是 A/B 比较的对象，差异由清单记录。每次重试固定的是各自开始时的发布版本；跨批次不一致时拒绝比较，而不是强行恢复历史版本。多变体实验整体锁定同一历史语料、真实 Agent 场景自动执行及其发布门槛仍是后续工作。

## 查询与界面

- `GET /api/evaluation/tasks/{taskId}/executions`：批次状态和清单。
- `GET /api/evaluation/executions/{id}/results?offset=0&limit=100`：分页归档结果，单页 1—1000 条。
- “检索评估”任务详情中的“执行批次与归档结果”可查看各次执行、语料摘要和原始回答。

接口只允许任务创建人读取，并重新检查当前知识库权限。人工复核和问题处理继续作用于当前 QA，不改写已存归档。显式删除评测任务时，其批次和结果通过外键级联删除；当前没有独立历史保留期限或归档清理管理界面。

## 升级与验证

先停止旧评测 Worker、排空旧执行，再执行 V41 并部署全部 API/Worker，最后恢复调度。禁止新旧评测写协议混跑。历史任务不补造批次；模型必须在模型目录中具有唯一、启用的匹配项，纯环境变量默认模型不会在严格评测中自动替代缺失条目。

本阶段验证包括模型配置修改后的缓存更新、固定模型目录、真实 SDK 到本机 HTTP 的连续调用、真实 MySQL 迁移/事务回滚/租约接管/取消恢复/归档保留，以及真实 Elasticsearch 的固定发布集合分块查询。故障注入验证了计数字段的非空约束，并据此修正重置协议。最终测试数量和证据见下方验收记录。
