# Agent 累计预算与取消状态完善

本轮在 V34 基础上修复预算和终止状态问题，不增加数据库迁移。部署仍需正常迁移至 V34，并遵循旧决策循环排空与全量后端切换要求。

## 修复后的行为

| 问题 | 当前行为 |
|---|---|
| 额度耗尽仍可反复申请恢复任务 | 恢复诊断、受理事务和 Worker 启动都检查累计预算；耗尽时拒绝入队，或阻止清理检查点和激活执行 |
| SDK 续跑按每次执行重新获得 Token 上限 | 传给 SDK 适配器的是原运行剩余额度，步骤也扣除已完成轮次 |
| 超额或后续模型异常丢失已有用量 | 每个 SDK 模型轮次结束后，先通过原执行租约保存 SDK 报告的累计轮次及用量，再检查是否超额 |
| 历史总量与输入/输出计数不一致 | 采用总量与输入/输出之和的较大值，未归属到输入/输出的历史用量在后续保存时继续保留 |
| 取消原因在后续检查点丢失 | 租约保留首次停止原因，失效后不再继续续约；后续检查点不复活执行或替换取消原因 |
| 主动取消被写成 FAILED | 沿异常原因链识别取消，Run 发布为 CANCELLED，恢复任务也按取消收尾 |
| 恢复激活后、领取租约前取消被写成 INTERRUPTED | 检查持久化任务的取消状态，将该运行写为 CANCELLED；准备失败仍为 INTERRUPTED |

## 预算领域边界

`AgentRunBudget` 集中定义默认 8 步、200,000 Token 上限、剩余量与合法计数。运行自带的 `max_steps` 优先于默认步数。负数计数或无效步数上限会阻止继续执行，不将异常数据解释为空预算。

legacy、AgentScope 与恢复策略复用同一预算对象，恢复不清零原消耗。累计输入/输出和历史总量比较使用长整数，计数累加采用溢出检查，避免整数回绕产生额外额度。

SDK `Usage` 回调属于应用运行端口，由应用服务在现有短事务和租约内保存计数；SDK 类型不进入业务服务。进度写入只更新计数，不通过旧 Run 对象覆盖运行状态、历史回答或心跳。异常后的失败收尾重新读取已持久化计数。

恰好用完额度的最终回答可以完成；下一次调用或恢复不再获得额度。恢复页面得到服务端的预算耗尽原因，不会仅凭“无业务动作”开放恢复。

## 取消领域边界

`AgentRunTermination` 统一区分 CANCELLED 与 FAILED，包括模型/SDK 包装过的取消异常。状态、历史回答和租约释放沿用原子发布机制；只有发布成功后才发送终态事件，失去执行权的旧任务不能用事件让聊天页误判新执行已经结束。

排队阶段取消仍由 V34 队列核对退回 INTERRUPTED，可由发起人重新申请；已经进入执行阶段的取消终结为 CANCELLED，不开放原运行恢复。尚未领取租约时的准备失败，不影响已领取执行权的 Worker。

取消是协作式停止，不保证即时中断已发送的模型请求。已提交业务动作有独立执行契约，本轮没有撤销或重新发送已提交动作。

## 验证与限制

真实 Spring/MyBatis/H2 事务测试覆盖预算耗尽拒绝受理、启动时二次预算校验、检查点保留、历史计数偏低及激活后领取租约前取消。SDK 测试使用真实 AgentScope 执行链和模拟模型，覆盖零额度不调用模型、超过剩余额度前回报用量，以及恰好额度的最终回答。

服务行为测试从 `AgentAskService.execute` 进入：模型报告用量后再失败，确认计数保留、历史未归属用量不丢失，并且没有申请业务动作。前端行为测试确认 CANCELLED 停止轮询且不转为可恢复失败。

验证结果：后端全量 161 项测试，160 项通过、1 项按环境配置跳过，0 失败、0 错误，打包成功；前端 8 项行为测试通过，`git diff --check` 通过。本轮前端变更仅新增行为测试，没有重复运行生产构建和全局类型检查。

这里的 Token 上限是应用层根据模型报告用量进行的运行限制，**不是供应商计费硬配额或预扣费协议**。检查发生在模型轮次结束时，已经发出的调用可能超出剩余额度；流式文本也可能先到达。进程强杀、响应中断、供应商未提供用量或数据库写入失败时，尚未持久化的消耗无法精确补计。没有宣称严格阻断所有并发工具/模型请求，也没有实现费用预留、对账或跨系统恰好一次。
