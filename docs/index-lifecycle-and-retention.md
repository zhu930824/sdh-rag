# 检索读租约与索引批次回收

V39 承接 V38 的发布指针协议，为固定读视图建立数据库租约，并按物理批次回收失效数据。自动删除默认关闭，所有节点升级到读租约协议后再启用。

## 读者与清理者的协调

一次检索先按知识库取得短暂的 SQL 协调锁，在同一事务中读取发布头集合、保存集合指纹、登记读租约，然后释放事务。代际引用按不可变版本登记一次，后续请求共享同一引用集合，每个请求只增加一条租约；嵌套查询共用根租约，根作用域关闭时只删除租约。回收通过版本引用与未到期租约联查保护读者。

协调行通过原子 upsert 直接取得排他锁。真实 MySQL 测试复现了“重复 INSERT 捕获异常，再 SELECT FOR UPDATE”引起的共享锁升级死锁，因此不再使用该方式。读取与回收使用同一个协调入口；发布事务仍通过 Job 租约、关联版本及物理写入标识约束发布权。

读取登记、租约校验和释放使用独立的 READ COMMITTED 短事务，避免外层 REPEATABLE READ 的旧快照看不到新租约，或者调用方回滚导致租约没有释放。事务不跨越 ES 或模型请求。

读租约默认 300 秒，为一次检索的绝对期限，不续期。构造查询前及公开搜索调用返回后均检查数据库租约。即使 ES 请求跨过期限后才返回，也会丢弃结果。过期异常携带业务码 503，普通聊天和 Agent 不会把它悄悄转为不带知识证据的回答；HTTP/SSE 仍沿用现有异常协议。用户重新提交问题会建立新读视图，不改变已有请求所固定的版本。

租约覆盖检索、查询改写、粗筛及重排阶段；片段已加载后生成答案不再需要占用索引租约。正常关闭释放失败时由 TTL 兜底；定时清理过期租约不依赖自动删除开关。

## 回收状态与保留窗口

| 条件/状态 | 行为 |
|---|---|
| 被发布指针或当前写入指针引用 | 不退休、不回收 |
| 首次发现失去指针引用 | 记录 `retired_at`，从此时开始计算保留窗口 |
| 有未到期读者引用 | 不领取删除任务 |
| 窗口到期且无读者 | 原子领取，写入 `DELETING`、独立 owner 和清理租约 |
| 部分失败、版本冲突或超时 | 保留 `DELETING`，延迟重试，不记录成功 |
| 四类索引均完成删除 | 记录 `DELETED` 和最后清理时间，安排后续复扫 |
| 清理进程失联 | 清理租约到期后其他节点可接管；旧 owner 不能覆盖回执 |

删除同时覆盖热片段、冷片段、热摘要和冷摘要。新格式按 `index_generation` 精确匹配；旧格式复用读取端的文档 ID + 旧逻辑版本 + 缺少新批次字段规则，旧摘要仅匹配无批次字段的对应文档。已移除按逻辑版本批量删向量和独立设置索引成功的旧入口，避免绕过新协议。

`DELETING` / `DELETED` 不能重新发布。ES 删除使用 `delete_by_query`，检查失败项、超时与版本冲突后再更新回执；重试允许前一次已删除部分数据。[Elastic 官方 API](https://www.elastic.co/docs/api/doc/elasticsearch/v8/operation/operation-delete-by-query)说明删除使用启动时的快照及内部版本判断，不能把 HTTP 请求完成等同于所有文档均删除成功。

迟到的过期写入可能发生在第一次删除之后。因此不删除代际墓碑，默认每天再次清理一次；旧批次始终不参与检索，复扫负责最终清除迟到片段或摘要。首次清理成功表示当次可见数据删除已确认，不表示之后永远没有迟到写入。

回收由专用单线程、零队列执行器完成，同实例不重叠，提交失败可再次调度。公共定时线程只做任务交接，避免批量 ES 删除阻塞可靠任务派发。

## 配置与上线

| `knowledge.index-lifecycle` 配置 | 默认值 |
|---|---|
| `cleanup-enabled` | `false` |
| `read-lease-seconds` | 300，范围 1—3600 |
| `retention-seconds` | 604800（7 天） |
| `cleanup-lease-seconds` | 300 |
| `retry-seconds` | 60 |
| `resweep-seconds` | 86400 |
| `batch-size` / `knowledge-batch-size` | 20 / 10 |
| `cleanup-interval-ms` | 60000 |

先保持 `KNOWLEDGE_INDEX_CLEANUP_ENABLED=false` 执行 V39 并升级全部 API/Worker，排空旧节点上的检索及写入，再按业务保留要求启用该环境变量。未升级的 V38 读者不登记租约，不能在新清理器运行时继续接流量。回退旧协议前先停止清理并排空任务，不能直接混跑。

`cleanup_attempts`、`cleanup_until`、`cleanup_error`、`last_cleanup_at` 和 `next_cleanup_at` 保留清理状态。长期失败会持续重试，需要修复 ES 可用性或冲突原因；清理不提供磁盘容量的绝对上限。数据库代际墓碑和读取集合档案作为审计元数据保留，尚未实现元数据归档/压缩及管理页面。仍被当前写入指针引用的失败批次会保留，重新入队或解绑后才能退休。

显式解绑和知识库删除仍使用原有业务删除流程，不承诺删除后旧读者继续获得内容，也不等同于全平台数据擦除。业务质量门禁与索引发布头的衔接、固定版本场景回归仍按后续顺序实施。
