# 历史评测语料重放（V42）

V42 在 V41 固定执行批次上增加“重放此批次”：使用已完成批次的实际问题集、知识库检索配置及发布集合，新建可靠评测任务。重放采用当前模型目录和当前程序，并保留新的配置指纹；它不是供应商模型权重或随机输出的逐字复现。

## 使用

在“检索评估 → 任务详情 → 执行批次与归档结果”中，对已完成批次点击“重放此批次”。后台创建新任务，原任务、问题及归档结果不被覆盖。新任务以原任务为基线，仍按 V41 的输入、语料、模式和 Top K 规则判断可比性。

API：`POST /api/evaluation/executions/{executionId}/replay`。

```json
{"requestKey":"client-generated-unique-request-key","judgeModel":"optional-model-selector"}
```

`requestKey` 为 16—64 位字母、数字、下划线或连字符。同一创建人重复提交相同请求会返回同一任务；同一键对应不同来源或评审模型则拒绝。界面在网络失败时保留该键供重试，成功后再次主动重放会创建另一个任务。`judgeModel` 省略时沿用源任务的选择器，实际客户端从当前模型目录创建。

来源必须是本人任务当前已完成的批次，创建和执行时都需具备知识库编辑权限。源输入、初始与最终清单均校验摘要；问题集和配置会复制到独立重放记录。执行时核对输入指纹，并在新的清单中记录 `replaySourceExecutionId`。

## 保留与回收协议

创建任务前，在同一知识库协调锁下检查历史发布清单和所有代际。语料必须尚处于可读的 PUBLISHED 状态，具有完整源摘要，且没有被撤回或与现存知识库关联不符。旧版无代际向量、已开始删除、已删除、业务回滚或来源证据不完整时拒绝重放，不会改用最新语料。

任务、冻结输入、排队 Job 和 24 小时语料保留记录在同一事务提交。队列写入失败时整体回滚，并发相同请求只产生一个任务。回收器在选取和认领删除对象时同时排除有效读租约及有效排队保留记录，因此不会在任务尚未开始时回收其语料。

执行开始后取得最长一小时的历史读租约。该视图只用于本次私有评测，不推进线上发布头；线上请求继续读取最新发布集合。完整成功时释放排队保留记录，失败重试期间保留到原定期限，终止任务恢复扫描也会释放对应记录。过期记录不再阻挡回收，并由既有回收扫描清理。

排队窗口过期后必须重新创建重放任务；如果历史向量已经回收，当前版本不会从原始文件自动重建。显式删除任务会级联删除重放配置，残余保留记录最多持续至原定到期时间。它不是无限期基线存储或备份制度。

## 升级

V42 新增 `knowledge_index_snapshot_hold` 和 `evaluation_replay_request`。升级时先停止并排空评测、索引发布和索引回收 Worker，执行迁移，部署全部 API/Worker 后恢复调度。禁止旧回收器与新重放协议混跑，否则旧回收器不识别保留记录。自动删除开关仍默认关闭，本次未部署生产或开启删除。

该阶段解决可用历史语料的重放及排队保护。跨整个多变体实验统一保留语料、归档向量恢复、真实 Agent 场景自动执行和质量门槛仍在后续路线内。
