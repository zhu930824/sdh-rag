# Agent 场景版本与运行结果归档

本轮在评测页增加“Agent 场景与结果”，支持导入业务场景、创建不可修改的后继版本、将自己的已结束运行关联到场景并保留结果快照。它是后续 Agent 轨迹评分的数据基础，记录状态为 `RECORDED`（已记录、未评分）。

## 使用路径

1. 升级应用数据库至 Flyway V35，打开“评测”中的“Agent 场景与结果”。
2. 下载场景模板，填写任务、初始上下文、允许/禁止工具、期望结果、关键步骤和风险等级，选择 JSON 文件并导入。
3. 选择场景版本及场景，填入自己已结束运行的 `runKey`，点击“关联运行并保存快照”。
4. 查看归档列表和快照。修改原聊天回答、配置或场景后继版本，不会修改已有归档。

关联操作只记录已有运行，不发起模型调用、审批或工具执行，也不会自动宣称任务通过。初始上下文及工具约束保存为评测期望，本轮不会将它们应用到一个新执行任务。

## 数据边界

现有 `test_dataset` 是 RAG 问答集，读取路径面向全局列表，且缺少 Agent 场景约束。直接塞入私有轨迹会扩大数据可见范围。本轮增加两个 Agent 领域表，复用既有 `AgentRun`、`AgentStep` 和 `ChatHistory` 作为证据来源，没有复制执行引擎或增加第二套任务队列。

| 数据 | 持久化方式 |
|---|---|
| 场景版本 | `agent_evaluation_dataset`；整份场景以有上限的 JSON 原子写入，含版本号、父版本、SHA-256、条数与所有者 |
| 场景期望 | 每条有稳定小写 ID、任务、上下文、工具约束、期望结果、关键步骤、风险枚举 |
| 运行记录 | `agent_evaluation_record`；保存场景期望副本、数据集哈希、运行证据 JSON 与其哈希 |
| 来源索引 | `dataset_id + scenario_id + run_key` 唯一，重复关联返回同一条记录 |

场景版本只追加，没有更新、覆盖或删除接口。首版为 v1，以某版本为父导入时创建 v(n+1)。父版本只能有一个直接后继，由数据库唯一键约束；并发创建时一个成功，另一个返回 409，需刷新后选择最新版本。

列表只查询当前用户最近 100 个版本/记录，单条读取也在 SQL 中包含用户条件。只能归档发起人为自己的运行；审批人能查看某次运行不意味着能将它归档到自己的评测集中。无权读取的版本、运行及记录返回 404，未登录返回 401。请求中的用户 ID 不能改变服务使用的登录身份。

只接受 `COMPLETED / FAILED / CANCELLED / REJECTED`，等待、执行中和可恢复中断都不是归档终态。回答行必须属于同一用户，并关联同一个 Run，否则返回 409。读取源运行、回答、步骤与写入归档使用同一个 REPEATABLE READ 事务。

## 快照的含义

归档保存来源 Run 已经记录的引擎、引擎版本、模型 ID、知识库 ID、记忆开关、预算、问答、证据预览、步骤、用量和时间。模型配置对象、凭据、认证头、工具 endpoint 与 SDK 消息存储不会整体序列化进入归档。

当前历史 Run 没有保存执行时的完整配置，因此以下字段明确为 `UNKNOWN`：模型配置版本、Prompt 版本、工具定义版本和知识发布版本。系统没有用归档时的最新配置冒充当时版本，也不能据此承诺精确重放。

V36 起的新执行批次会记录配置指纹，归档 schema v2 会复制这些批次并区分 `COMPLETE / PARTIAL / NONE`。完整历史有多份配置时顶层标为 `MULTIPLE`；旧记录不自动改写。详细边界见 [执行批次配置快照](agent-execution-attempt-snapshots.md)。配置指纹不等同于完整配置原文或精确重放材料，知识发布版本仍未固定。

快照最多保留 50 个步骤，参数/结果分别保留 2 Ki/6 Ki 字符预览；问答、检索证据和错误也有独立上限。记录 `recordedStepCount`、整体 `truncated` 和每步 `truncated`，始终序列化完整 JSON，不截断 JSON 字节流。预览不能作为完整工具参数评分的替代输入。

## 导入约束与接口

单版本 1—100 条场景，规范化后场景 JSON 不超过 1 MiB。服务端验证名称、任务、期望结果、ID、字段长度、列表长度与重复项，拒绝允许/禁止工具重叠及缺失风险等级；ID 只接受小写字母、数字、下划线及短横线，避免数据库不区分大小写时出现歧义。字段限制在写入前统一执行。

```json
{
  "name": "售后场景",
  "scenarios": [{
    "id": "after-sales-ticket",
    "task": "为订单 42 创建售后工单",
    "initialContext": "客户已确认申请售后",
    "allowedTools": ["get_order", "create_ticket"],
    "forbiddenTools": ["delete_order"],
    "expectedOutcome": "核对订单后经审批创建一个工单并返回编号",
    "criticalSteps": ["核对订单", "请求审批", "返回工单编号"],
    "risk": "MEDIUM"
  }]
}
```

| 接口 | 用途 |
|---|---|
| `POST /api/agent/evaluation/datasets` | 导入新版本；可加 `parentId` 指定父版本 |
| `GET /api/agent/evaluation/datasets` | 当前用户版本列表 |
| `GET /api/agent/evaluation/datasets/{id}` | 版本与完整场景 |
| `POST /api/agent/evaluation/records` | 关联 `{datasetId, scenarioId, runKey}` |
| `GET /api/agent/evaluation/records?datasetId=...` | 指定版本的当前用户记录摘要 |
| `GET /api/agent/evaluation/records/{id}` | 场景与运行证据归档 |

离线 SDK 协议种子集中的固定模型响应、预算和检查点字段属于测试夹具，不能直接冒充业务场景导入。两类数据用途不同，前一批 [离线回归门禁](agent-scenario-regression.md) 保留原入口。

## 验证与行动记录

- 先增加导入、版本、归档、所有权和幂等行为测试，空实现按预期失败，再补充生产实现。
- 将场景作为不可变整体保存，避免批量导入时出现半份数据及版本覆盖；数据库唯一键控制并发后继及重复归档。
- 以字段白名单构造运行证据，标明未知配置和预览截断，不猜测历史版本。
- 接入评测页，选择版本时清空旧场景/记录并隔离过期请求；隐藏不适用于 Agent 归档的 RAG 运行配置。
- 增加 HTTP 请求格式、用户隔离、边界长度、大轨迹、回滚测试；扩展真实 MySQL 迁移与竞争验收。

验证结果（2026-11-04）：

- 新增服务/HTTP 行为测试 8 项全部通过，包含用户隔离、输入边界、不可变版本、原始回答关联、大轨迹、幂等及回滚。
- 完整后端 `verify`：212 项普通测试，211 项通过、1 项按原配置跳过；打包成功。
- 真实 MySQL：12 项全部通过，无跳过；V1—V35 迁移、校验及重复执行通过，新增并发归档、旧快照幂等读、版本竞争通过。自建测试数据库及 Worker 均已退出。
- 前端 8 项既有行为测试通过。新增页面类型问题已修正，全局类型检查仍报告原有 320 项诊断；去除行号后与原基线逐项一致，无新增诊断。全局类型检查尚未通过。
- 前端生产构建通过；没有连接运行中的业务环境做浏览器验收，也未调用真实模型或执行生产动作。

执行日志位于忽略目录 `.workbuddy/agent-evaluation-*.log`。当前工具环境没有 crapper、dryer、mutator，未声称通过这些工具的检查。
