# 业务质量门禁与索引发布协议

V40 把知识草稿的回归门禁放进可靠索引任务，完成“审核内容—候选索引—回归验证—线上发布头”的衔接。原流程先发布向量，再由发布列表执行验证并尝试移除失败文档，存在提前可见窗口；列表现在只读，发布进度不再依赖用户打开页面。

## 发布流程

1. 草稿至少配置一个回归问题才能提交审核。允许 1—10 个问题，每个不超过 500 字符。尚未产生发布文档的已批准草稿可以重新编辑，编辑后回到 DRAFT 并清除旧审核信息，须重新审核。
2. 发布操作锁定草稿，校验审核记录及正文。生成不超过 1 MiB 的规范 Markdown，上传对象存储；文档、关联、PUBLISHING 状态、发布记录和索引 Job 在同一个数据库事务中创建。
3. Worker 对受管草稿读取原始文件字节，计算 SHA-256。登记 STAGING 批次时，必须与审核正文和标题生成的规范文件一致；同时冻结回归问题、审核人、模型选择、Top K 和算法版本。
4. 所有片段写入并刷新后，Worker 打开专用候选视图：以当前已接纳发布集合为基线，仅将目标文档替换为本次物理批次。候选作用域有读租约，正常请求仍只使用线上发布集合。
5. 对每个问题执行严格向量检索，必须在 Top 5 中命中目标文档的本次物理批次。旧批次、同文档不同片段代际以及其他文档都不能替代候选命中。
6. 保存不可覆盖的验证回执。通过后再次校验 Job 所有权、关联版本、写入批次、门禁策略和检索基线，在同一事务内更新技术发布头、草稿业务发布批次、文档状态及发布审计。

普通文件上传的索引流程仍保留原有内容过滤和自动发布行为；新增回归门禁适用于知识草稿发布及这些受管文档的重新索引。受管草稿不能通过另建其他知识库关联绕过原发布边界。

## 可见性与一致性

线上读视图同时检查技术发布头和草稿的 `published_generation`。技术行标记为 PUBLISHED，但没有对应业务接纳批次时，不参与检索。业务已回滚的草稿即使仍有残留技术指针，也不会重新可见。

检索基线版本是评测开始时的已接纳代际集合指纹；候选版本是替换目标批次后的集合指纹。最终发布取得知识库协调锁并执行当前读，如果基线已变化就拒绝本次发布，由可靠任务重新准备物理批次并验证，不能复用旧基线上的通过结论。

读者登记、暂存、门禁回执、发布与回收共用知识库协调行。发布相关事务先协调，再校验 Job 租约和关联。候选门禁的 ES 请求及嵌入调用在这些短事务之外执行，不持有这些行锁。

| 结果 | 发布头与业务状态 |
|---|---|
| 所有问题命中本次候选 | 保存 PASSED 回执；事务提交后新批次才进入线上检索 |
| 回归未命中或没有有效片段 | GATE_FAILED；不移动线上头；释放失败批次的写入指针，使其可按保留策略回收 |
| 重建已有发布文档时门禁失败 | 保留原已接纳批次，不自动删除仍有效的旧版本 |
| ES、嵌入或租约等基础设施失败 | 不产生 FAILED 质量结论；保留待完成回执，任务按可靠重试策略处理 |
| 发布事务任一步失败 | 技术头和业务状态共同回滚；已保存的验证回执用于审计，不等于已发布 |
| 任务取消或重试耗尽 | 定时检查终态 Job，将滞留的 PUBLISHING 草稿标记发布失败，不执行模型或检索 |

索引失败状态回写也校验当前 Job 租约及物理写入批次，过期执行不能覆盖接管者的诊断或发布状态。重试会建立新的物理批次及门禁回执；发布重放保持幂等，不重复改写通过结论或成功审计。

## 记录与接口

`knowledge_index_publication_gate` 以 `generation_key` 为主键，保存：

- `draft_id`、冻结的 `policy_json` 及 `policy_sha256`；策略包含源文件指纹、问题集合、审核信息、模型选择、Top K、算法标识和 schemaVersion。
- PENDING / PASSED / FAILED 状态。
- `basis_sha256`、`candidate_sha256`、逐问题结果和检查时间。

回执及其关联代际保留用于审计。VALIDATE 发布记录带上物理批次与两个版本指纹。只有成功提交的批次才写入草稿 `published_generation`。

已有 `/validate` 是发布后的健康检查，不是发布许可。它仅按当前草稿发布批次条件更新验证字段；并发回滚或版本改变时拒绝更新，不能用旧实体快照覆盖业务状态。它不会改写已冻结的索引门禁回执，也不会因为一次健康检查失败自动撤回旧发布头；撤回继续使用受控回滚入口。

发布失败时，数据库文档、关联、审计和 Job 一起回滚；对象存储通过事务回滚回调尽力清理。对象存储不属于数据库事务，进程在上传后崩溃等情况仍可能留下孤立文件，需要后续对象生命周期治理，不能宣称跨存储原子提交。

## 历史数据与上线

V40 为历史 PUBLISHED 草稿登记当时关联的已发布代际，保留既有业务发布，不补造新门禁的 PASSED 回执。历史记录缺少回归问题或审核信息时，不能据此声称通过了本版本门禁。

迁移清除旧 PUBLISHING、GATE_FAILED、PUBLISH_FAILED、ROLLED_BACK 草稿的技术发布头。PUBLISHING 关联推进逻辑版本并进入待处理恢复，旧 Job 因版本和任务绑定变化不能提交结果；失败及回滚关联保留失败状态。缺少有效问题或源文件不一致的旧内容仍会被新协议阻断，不自动放宽策略。

部署需先停止旧 Worker 并排空旧请求，执行 V40，部署全部 API/Worker 后再恢复调度。不支持 V39 发布 Worker 与新门禁混跑。V39 的自动回收开关仍默认关闭，本阶段没有修改线上开关或部署生产。

## 保证范围与后续工作

门禁证明候选批次在指定问题的 Top 5 中可召回，不证明正文事实准确、答案正确或满足完整业务流程。低相似度但仍排进 Top 5 的结果也属于召回命中，不能把这一门禁当成语义质量评分。

策略记录并约束嵌入模型选择，尚未冻结供应商侧权重或同名配置背后的完整参数。基线集合变化会阻断发布；这不是所有配置和外部模型行为完全固定的可复现评测协议。下一阶段继续绑定场景运行、完整配置指纹、固定版本基线及评测门槛。

候选片段仍位于共享 ES 索引，但仅候选作用域可查询。管理端物理片段预览、显式删除和后续元数据归档不等同于线上检索发布承诺。暂存与失败批次沿用 V39 的精确回收和墓碑复扫。
