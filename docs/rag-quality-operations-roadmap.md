# RAG 与 Agent 质量运营升级路线图

## 目标

把当前“可以运行并查看指标”的评测模块，升级为连接真实业务反馈、评测数据、知识发布和 Agent 运行的质量运营闭环。

```text
线上反馈/失败轨迹
        ↓
候选测试样本 → 人工标注 → 版本化数据集 → 分层评测
                                      ↓
                              基线比较与失败归因
                                      ↓
                        知识发布门禁 / Agent 发布门禁
                                      ↓
                              上线观测并继续回流
```

## 阶段与验收标准

### 阶段 A：数据集可运营化（本轮执行）

- [x] 文档和分块可视化选择，不再要求用户手写内部 ID。
- [x] 支持为多个相关文档设置 0-3 级相关性。
- [x] 数据集显示版本；增删、编辑、导入样本后自动递增版本。
- [x] 评测任务保存数据集 ID、数据集版本和完整配置快照。
- [x] 内置数据集可复制为自定义业务数据集后继续标注。

验收：用户能在一个页面完成“复制样例 → 选择知识库 → 绑定相关文档/分块 → 运行固定版本评测”。

### 阶段 B：质量门禁与诊断（本轮执行）

- [x] 逐题生成失败类型和改进建议。
- [x] 区分缺少标注、检索遗漏、Context 噪声、生成幻觉、回答不完整与拒答失败。
- [x] 知识草稿配置回归问题后，完成索引时自动执行 Top-5 门禁。
- [x] 门禁失败的知识不得进入已发布状态，并从检索链路移除。
- [x] 发布审计记录门禁结论。

验收：一次不合格知识发布能够被自动阻断，并能定位失败发生在检索还是生成环节。

### 阶段 C：真实业务样本回流（本轮执行基础闭环）

- [x] 点踩反馈可以加入指定测试数据集。
- [x] 自动带入真实问题、人工修正答案、知识库访问校验和反馈来源。
- [x] 同一反馈不能被重复加入同一数据集。
- [x] 回流完成后自动标记反馈为已处理。

验收：运营人员无需复制粘贴即可把线上失败问题加入回归集。

### 阶段 D：实验与持续评测（本轮完成）

- [x] 建立实验、变体、运行批次和运行任务实体，支持多个检索/生成配置同批对比。
- [x] 支持按场景、难度、业务线和用户角色切片统计，并显示失败率与分层指标。
- [x] 支持 Spring Cron 定时回归、单批 LLM 评审预算、最多 3 次失败重试。
- [x] 通过现有 Webhook 机制发送 `evaluation.regression` 与 `evaluation.run_failed` 告警。
- [x] 支持人工复核队列、五维人工评分和 LLM-as-Judge MAE/一档内一致率。

验收：用户能在“评测实验室”用固定版本数据集创建至少两个变体，手动或定时运行；运行完成后可对比指标、下钻业务切片，并通过人工复核观察自动评审偏差。

### 阶段 E：Agent Evaluation（下一阶段）

- [ ] 任务完成率、工具选择准确率、参数正确率和无效调用率。
- [ ] 执行轨迹回放、步骤数、耗时、Token 和成本。
- [ ] 审批触发准确率、越权尝试和安全策略命中。
- [ ] Agent 失败轨迹一键转成回归场景。

阶段 E 的功能范围、数据模型、测试数据构成和验收标准见 [平台升级方向与演进路线图](platform-evolution-roadmap.md)。

## 数据与架构约束

1. 评测任务必须保存不可变的 QA 副本，因此数据集后续修改不会污染历史结果。
2. 基线比较仅允许同一知识库、同一评测层级和同一 Top K。
3. 未标注文档的样本不参与经典检索指标，也不应被错误归因为检索失败。
4. 自动评审只负责规模化筛查；门禁失败和高风险业务场景仍应支持人工复核。
5. 发布门禁必须可审计，失败内容保留源文档记录，但不得继续出现在检索结果中。
6. 定时实验必须绑定创建人并在执行时重新校验知识库编辑权限，权限被撤销后不得继续运行。
7. 单批评审预算按“非检索变体数 × 数据集样本数”预估，超限时在创建任何评测任务前阻断。

## 推荐运行制度

- 检索配置变化：运行 RETRIEVAL 固定集。
- Prompt 或生成模型变化：运行 GENERATION 固定集。
- 知识发布及版本发布：运行 FULL，并与最近通过基线对比。
- 每周：把线上失败反馈整理进业务回归集。
- 每月：抽样校准 LLM-as-Judge 与人工评分的一致性。

## 阶段 D 使用说明

1. 在“检索评估”中准备版本固定的数据集，标注场景、难度、业务线、用户角色和相关文档。
2. 进入“评测实验室”，选择知识库和数据集，至少添加两个变体。检索变体不产生自动评审调用；GENERATION/FULL 变体计入预算。
3. 需要持续回归时启用 Spring 六段 Cron。扫描器默认每 30 秒发现到期实验，同一实验不会重叠运行。
4. 异步任务失败会按实验配置自动重试；重试耗尽或基线回归时触发对应 Webhook 事件。
5. 在“场景切片”选择任务与维度定位薄弱业务，在“人工复核”用 1-5 星修正评分并查看人机偏差。

实现数据表由 `V27__evaluation_experiment_operations.sql` 创建。评测任务只在事务提交后进入执行线程，避免调度批次刚创建时异步线程读取不到任务记录。
