# RAG 检索证据与索引代际追溯

本轮修复索引代际在搜索结果转换时丢失、同文档多片段引用只留下第一段的问题，并为 Agent 保存不可改写的检索证据观察快照。普通问答与 Agent 问答共用来源组装规则，历史聊天仍能展示旧格式来源。

## 数据链路

1. 文档索引处理对实际解析出的全文计算 `indexed_content_sha256`，与任务的 `index_revision` 一起写入每个向量。
2. 向量写入端对最终写入的片段文本计算 `chunk_content_sha256`，覆盖调用方传入的同名值，避免保存不对应文本的校验值。
3. 向量、关键词、指定文档及冷索引检索保留命中 ID、索引代际与两类内容指纹。级联检索的热/冷结果都携带这些字段。
4. 返回片段再次计算实际文本指纹，记录是否与索引保存的片段指纹一致。缺失或非法代际不变成 0 或当前文档版本。
5. 来源按文档分组展示，但 `chunks` 保留该文档全部召回片段及其代际、指纹、分数和截断信息。旧的文档级内容、分数和字段保留兼容。

这些标识描述实际读到的向量，不查询可变文档行来猜测旧片段所属版本。旧向量没有新字段时，保留内容并明确元数据不完整；不会后台补上一个未经证明的全文版本。要获得新索引指纹，需通过已有可靠索引任务重新索引。

## 检索快照

Flyway V37 为 `agent_run` 增加 `retrieval_snapshot_json`。初次检索完成后随 Run 创建一次插入，常规实体更新不修改它；审批续跑、安全恢复和终态发布均保留原快照。

快照的 `scope` 是 `RETRIEVED_CANDIDATES`，包括完整检索上下文的哈希和长度，以及每个返回片段的来源、内容指纹和内容预览。每个片段最多保存 12000 字符，超过时标明 `truncated`，哈希仍覆盖完整片段。

`generationCoverage` 表示召回片段的索引元数据覆盖程度：

- `COMPLETE`：每个片段均有向量 ID、有效代际、全文指纹，且索引片段指纹与实际文本一致。
- `PARTIAL`：仅部分片段满足这些条件。
- `NONE`：没有片段具备完整且校验一致的代际元数据；不代表它们没有可用内容。

同一文档出现不同代际或全文指纹时，`mixedGenerations=true`，引用卡与详情会提示用户核对。即便每个片段的元数据都完整，也可能混合多个代际，覆盖程度不是原子发布一致性判断。

Agent 的提示词证据仍沿用 12 Ki 字符上限，Run 的 `evidence_text` 是实际传入提示词构造的证据；检索快照保留的是截断前的候选集合。两者分别计算指纹，不能将候选快照误认为所有原文都进入了模型。

执行批次配置指纹增加检索快照哈希，评测归档 schema v3 复制原始检索快照与其哈希。原始文档、索引或配置发生后续变化，不会改变已经创建的 Run 和归档中的观察记录。

## 前端使用

聊天来源卡会显示召回片段数量；点击后逐段展示内容、分块序号、索引代际和片段指纹。内容预览被截断时有单独标记；没有 `chunks` 的历史记录继续显示旧来源正文。读取来源使用既有会话/运行访问控制，没有新增全局可读的检索档案接口。

## 尚未完成的发布边界

本轮没有固定整个知识库的原子发布版本，`publicationVersion` 仍为 `UNPINNED`。当前索引更新期间仍可能读到多个代际，本轮负责记录并展示这一事实，不以指纹或 `COMPLETE` 代替发布承诺。

下一步需要引入明确的索引代际发布可见性：未完成代际不参与线上检索，固定一次检索读到的已发布代际集合，并在清理旧代际前保护正在使用它的请求。然后再把该版本与可靠场景执行和评测基线绑定。
