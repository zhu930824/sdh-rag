# 业务 Agent 执行与运营闭环

## 当前能力

平台已从“知识问答”扩展为“知识 + 行动”平台：

1. 在业务工具中心登记固定 endpoint、HTTP 方法、参数 JSON Schema、风险等级和审批策略。
2. 工作流可使用“受控工具”节点；聊天可开启 Agent 模式，由支持工具调用的模型自主选择工具。
3. 中高风险动作先写入 `agent_action`，进入人工审批；批准后才调用业务系统。
4. Agent 运行、模型步骤、工具步骤和审批状态分别落入 `agent_run`、`agent_step`、`agent_action`。
5. 审批完成后，聊天 Agent 或确定性工作流从暂停点继续执行，不重复已执行节点。
6. 用户可反馈真实业务结果，并把可复用经验送入知识与流程改进队列。
7. Agent 运营页展示任务完成率、工具成功率、待审批量、业务反馈和每日趋势。

## 数据迁移

- `V20__agent_action_governance.sql`：工具、动作和业务反馈。
- `V21__agent_run_and_trace.sql`：Agent 运行、步骤轨迹、聊天/工作流续跑字段和演示工单。
- `V22__seed_demo_agent_tools.sql`：订单、库存、售后工单演示工具。
- `V23__agent_operations_improvement.sql`：知识与流程改进队列。

部署时必须按顺序应用 V20-V23。演示工具的审批人默认是用户 ID 1；正式环境应按组织审批关系调整。

## 安全边界

- 外部工具默认只能使用 HTTPS。
- 默认禁止访问回环、链路本地、组播和私网地址。
- 明文凭据不入库，只允许 `env:VARIABLE_NAME` 引用。
- 普通用户不能登记 `internal://` 工具，避免绕过内置工具的风险与审批策略。
- 请求体最大 256KB，响应体最大 2MB，超时范围 3-120 秒，禁止自动跟随重定向。
- `(tool_id, requested_by, idempotency_key)` 唯一，避免重复业务操作。
- 手工续跑会校验关联动作已经全部审批并执行，不能绕过审批闸。
- 工作流执行和审批续跑使用有界线程池。

## 审批状态

`PENDING_APPROVAL → READY → EXECUTING → SUCCEEDED/FAILED`

拒绝路径为 `PENDING_APPROVAL → REJECTED`。聊天 Agent 和工作流只有在所有关联动作均完成决定后才能续跑；多动作场景中任一拒绝会以拒绝结果收尾。

## 运营指标口径

运营报表按当前登录用户和所选时间范围统计：

- Agent 任务数、完成/失败/等待审批/拒绝数；
- 平均步骤数和 Token 总量；
- 工具调用总量、成功/失败/拒绝/待审批数；
- 各工具调用量与成功率；
- 真实业务结果反馈数、业务失败数和可沉淀知识数；
- 每日任务、完成和失败趋势。

## 知识改进闭环

动作执行成功后，用户在审批与执行页反馈真实业务结果。选择“可沉淀为知识”会自动创建 `KNOWLEDGE_REUSE` 改进项，并尽可能关联 Agent 使用的知识库、运行、动作、请求参数与工具结果。知识运营人员在“Agent 运营与改进”中处理并记录结论。

当前队列负责发现、分派语义和闭环留痕，不会自动把未经审核的业务反馈写入向量库。后续可在改进项解决时增加“生成知识草稿 → 审核 → 发布 → 回归评测”的发布流水线。

## 主要入口

- `/agent-tools`：业务工具中心。
- `/agent-actions`：审批与执行记录。
- `/agent-ops`：Agent 运营与改进。
- `/chat`：开启 Agent 模式后进行知识驱动的业务任务。
- `/workflow`：使用受控工具节点编排确定性业务流程。
